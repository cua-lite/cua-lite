# CUA-Gym Upstream Issue Log

This file records upstream task or mock defects observed while integrating
CUA-Gym. The adapter does not patch upstream task bundles or mock business
logic. It does **annotate** the rows that are unusable as default training
signals — see [Task Exclusion Vocabulary](#task-exclusion-vocabulary) — but it
never DROPS one: all 10,910 pinned upstream rows (1,505 web + 9,405 desktop, the
on-disk catalogs) remain registered, and the caller decides what to run. A
failing task is recorded and skipped by the rollout pipeline without aborting
sibling tasks.

Official task materials are mirrored unchanged in
`cua-lite/lite.cuagym-assets`. The mock Hub is pinned to upstream commit
`53205689c3d88078c1375f76466d5bd799478828`; CUA-Lite does not patch mock
business logic.

## Task Exclusion Vocabulary

`EXCLUDE_REASONS` in
[/lite/gym/envs/lite/cuagym/src/utils/dataset.py](/lite/gym/envs/lite/cuagym/src/utils/dataset.py)
is the closed vocabulary for `metadata.others.exclude_reason`.
The contract is annotate-don't-drop, in three places:

1. **Import** tags a row when the defect is decidable from the pinned bundle
   alone or from a confirmed visual rollout of the pinned bundle —
   `dataset.reward_defect()` for the three mechanical reward classes,
   `dataset.instruction_defect()` for a row that states no task, the
   curated task ids for setup defects, and revision-pinned validation findings.
   Measured on the pinned snapshot: **513 of 10,910** on-disk rows (4.70%) —
   98 web + 415 desktop, leaving 10,397 untagged. By category:
   152 `broken_reward:empty`, 81 `broken_mock:blank_render`, 42
   `broken_reward:no_sentinel` (26 desktop + 16 web), 26
   `broken_reward:syntax_error`, 19 `broken_reward:missing_golden`, 1
   `broken_setup:unsatisfiable_gate`, 8 `broken_setup:external_dependency`, 1
   `broken_setup:wrong_backend`, 2 `broken_setup:missing_seed_file`, 1
   `broken_setup:syntax_error`, 1 `broken_setup:no_task_window`, 178
   `broken_reward:instruction_mismatch`, 1 `broken_task:empty_instruction`.
2. **Load** — `catalog_task_ids` REJECTS a catalog carrying an
   `exclude_reason` outside the vocabulary, so the tag cannot drift into prose.
3. **Setup** — `guard_excluded` in
   [/lite/gym/envs/lite/cuagym/main.py](/lite/gym/envs/lite/cuagym/main.py)
   wraps both backends' `setup_fn` and refuses a tagged row on the first line of
   setup with `CuaGymTaskError(phase="setup", kind="excluded_task")` — before any
   mock start, bundle upload, or GUI launch, and before a single agent step.
   That is a terminal env/setup error, not a reward-0 trajectory, and it
   matches the sibling `lite.scalecua` guard
   ([/lite/gym/envs/lite/scalecua/src/osworld/setup.py](/lite/gym/envs/lite/scalecua/src/osworld/setup.py))
   so an unfiltered run of either env dies at reset rather than burning an
   episode.

Consumers opt out with the same one-liner every other env uses:

```bash
--filter "lambda m: not m.others.get('exclude_reason')"
```

## Known Task-Asset Defects

The pinned corpus includes examples of:

- empty or syntactically invalid `reward.py`;
- setup/reward scripts that rely on unavailable network or privileged host
  services;
- web-labelled tasks that also assume desktop filesystem state;
- rewards that are nonzero before the agent acts;
- setup flows that open no usable task window.

The last one is only a defect when an opener actually ran: the desktop setup
demands a new window when `task.json` declares an `open` step or the setup
script itself launches a GUI, and otherwise logs and continues, because a
file-seeding bundle whose instruction tells the AGENT to open the app was never
going to raise a window.

These are all upstream data-quality issues; the adapter fixes none of them. The
subset that is decidable from the pinned bundle, or from a confirmed visual
rollout whose cause is the pinned bundle, is tagged at import (see
[Task Exclusion Vocabulary](#task-exclusion-vocabulary)), so those task IDs come
straight out of the catalog:

```bash
jq -r 'select(.metadata.others.exclude_reason) | [.task_id, .metadata.others.exclude_reason] | @tsv' \
  lite/gym/envs/lite/cuagym/.cache/{web/lite.cuagym_tasks,desktop/lite.cuagym_desktop_tasks}/train.jsonl
```

The rest — the ones only a rollout can reveal (nonzero-before-acting rewards,
cross-platform state assumptions) — still have to be read off rollout error
artifacts when they are sampled.
